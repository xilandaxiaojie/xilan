# 启动失败排查

## 先说结论：有个一定能用的版本

如果桌面版怎么都打不开，**直接用浏览器版**：

```
studio/release/浏览器版/点击启动.bat
```

双击它，会打开浏览器作为界面，功能几乎一样（除了在线登录 GitHub 和克隆仓库）。
不需要装任何东西——里面自带了 Node 运行时。

浏览器版的限制：需要你事先把仓库 clone 到本地，然后点「打开已有目录」选它。

---

## 桌面版排查

### 已确认的现象

运行 `诊断.bat` 得到的典型输出：

```
[1] 环境变量
    ELECTRON_RUN_AS_NODE = []          ← 干净
[3] 检查文件
    exe: 存在 / app.asar: 存在 / icudtl.dat: 存在
[4] 启动（全量日志）
--------------------------------------------
--------------------------------------------            ← 一行日志都没有
[5] 退出码 = -2147483645
```

**关键点**：`--enable-logging` 时 Chromium 正常会输出几十行初始化日志。
**零输出**说明进程在 Chromium 初始化之前就被中断了，不是应用代码的问题。

这种情况通常是下面几种原因之一。

---

### 原因 1：安全软件拦截（最常见）

360、火绒、Windows Defender 的「受控文件夹访问」等，
会静默杀掉未签名的 Electron 程序。

**做法：**

1. 把 `release/Xilan Studio-win32-x64` 整个文件夹加入杀毒软件白名单
2. 临时关闭「受控文件夹访问」：
   Windows 安全中心 → 病毒和威胁防护 → 勒索软件防护 → 管理勒索软件防护 → 关闭
3. 再双击试

在 Windows 安全中心 →「保护历史记录」里能看到有没有拦截记录。

---

### 原因 2：系统缺少运行库

Electron 依赖 VC++ 运行库。虽然通常系统自带，但精简版系统可能没有。

安装微软官方的 **Visual C++ 2015-2022 Redistributable (x64)**：
<https://aka.ms/vs/17/release/vc_redist.x64.exe>

---

### 原因 3：显卡驱动 / 远程桌面

试这些参数（把 `诊断.bat` 拖到命令行后面带上）：

```powershell
cd "D:\DSH\博客\studio\release\Xilan Studio-win32-x64"
.\"Xilan Studio.exe" --disable-gpu
.\"Xilan Studio.exe" --disable-gpu --disable-software-rasterizer --no-sandbox
```

---

### 原因 4：环境变量干扰

虽然你的诊断显示是干净的，仍然可以彻底确认一遍：

```powershell
[Environment]::GetEnvironmentVariable("ELECTRON_RUN_AS_NODE", "User")
[Environment]::GetEnvironmentVariable("ELECTRON_RUN_AS_NODE", "Machine")
```

两个都应该输出空。如果有值：

```powershell
[Environment]::SetEnvironmentVariable("ELECTRON_RUN_AS_NODE", $null, "User")
```

---

### 原因 5：文件被阻止

```powershell
Unblock-File "D:\DSH\博客\studio\release\Xilan Studio-win32-x64\Xilan Studio.exe"
```

或者右键 exe → 属性 → 勾选「解除锁定」→ 确定。

## 我有把握的部分

虽然图形窗口在当前开发环境里起不来（同样是缺少图形会话），
但**程序的功能代码已经全部验证过**，包括在打包后的 exe 里：

```powershell
cd "D:\DSH\博客\studio\release\Xilan Studio-win32-x64"
$env:ELECTRON_RUN_AS_NODE = "1"
.\"Xilan Studio.exe" "D:\DSH\博客\studio\scripts\test-packaged-runtime.mjs"
```

这条命令会用打包产物里真正的 Electron 运行时跑一遍
「创建文章 → 写入 frontmatter → 读回 → 渲染 Markdown」，
结果是 10 项全通过。

所以如果只是窗口打不开，**业务逻辑本身是好的**，问题出在 Electron 外壳的启动环节。

---

## 还是不行怎么办

把 `诊断.bat` 的完整窗口内容（尤其 `[4]` 那一段，哪怕空白也说一声）发出来。

同时可以立刻切换到浏览器版开始写文章，不用等这个修好。
